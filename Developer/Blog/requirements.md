# Requirements — Blog

Universal requirements (see Core) always apply.

## Requirements (must pass)

- [ ] Plain language: jargon defined on first use
- [ ] No fabrication: no source → no fact
- [ ] Evidence tags used correctly; receipt = source + warrant
- [ ] Valid `app.yaml` present and accurate
- [ ] No personal or private material in shipped files
- [ ] Follows Core authority model (Steward disposes)
- [ ] Steel-man the other side before rebuttal in published work
- [ ] Memory claims capped at [Likely] and admitted in prose when published
- [ ] Nothing publishes without Steward’s explicit word

## Nice-to-haves (should improve)

- [ ] Seeds organized by topic with status fields
- [ ] Clear link from seed → reference or briefing when relevant
- [ ] Style-anchor kept current
- [ ] Consistent with debate-guide and conversation-framework when engaging objections

## Graduation

May move to Apps/ and GitHub only after the Steward audits it against these lists and gives explicit approval.
